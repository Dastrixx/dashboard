# Локальная аналитика: продажи и маржа

API сохраняет готовые результаты запросов продаж и маржи в `data/analytics.sqlite`.
При повторном открытии периода ответ читается с диска, без ожидания 1С.
Перезапуск Node не удаляет результаты. Авторизация хранится в отдельной базе.

## Запуск

Обновите код, оставьте существующие параметры подключения к 1С и перезапустите API.
Режим включён по умолчанию. Настройки `.env`:

```dotenv
ONEC_LOCAL_ANALYTICS=true
ONEC_ANALYTICS_DB_PATH=data/analytics.sqlite
ONEC_SYNC_INTERVAL_MS=300000
```

Папка `data` должна находиться на постоянном диске и быть доступна процессу Node
для записи. Для Docker подключите её как volume. Этот режим предназначен для
одного процесса Node API на сервере; несколько экземпляров требуют общего
хранилища и распределённой очереди. SQLite-файл не нужно коммитить в Git.

При старте очередь прогревает продажи за текущие 30 дней, предшествующие 30 дней,
маржу текущего периода и справочники продаж. Очередь выполняет один отчёт за раз.
Первая загрузка может занять несколько минут и всё ещё зависит от доступности 1С.
Незагруженный период возвращает HTTP 503 с кодом `ANALYTICS_SYNC_PENDING` и
`Retry-After: 10`; интерфейс автоматически проверяет готовность. Ошибка 1С
показывается явно, а не превращается в нулевые продажи.

## Обновление и корректность

- Каждые пять минут обновляются периоды, использовавшиеся в последние сутки.
- Полный успешный ответ заменяет старый одной записью SQLite. Частичный ответ
  за заданный диапазон или ошибка не затирают предыдущий результат.
- Периоды перечитываются целиком, поэтому изменения задним числом, отмена
  проведения и удаление документов отражаются при следующем успешном обновлении.
- Дата документа не используется как дата его последнего изменения.
- Ошибка обновления сохраняет прежние данные с признаком `stale` и временем
  последнего успешного получения. Повторные обращения не дублируют задание.
- После изменения URL базы или пользователя 1С используется отдельное пространство
  снимков: старые данные другой базы не будут показаны.
- Неиспользовавшиеся 30 дней снимки очищаются. Активные периоды продолжают обновляться.

`GET /api/dashboard/sync-status` доступен после входа владельцу и менеджеру.
В ответах отчётов есть `meta.localSync` с `syncedAt`, `stale`, `refreshing`, `error`.
Панель на странице показывает периоды и даты обновления. Продажи и маржа могут
иметь разные даты синхронизации; единого транзакционного снимка всей 1С нет.

## Границы первого этапа

Это постоянные снимки рассчитанных отчётов, а не полная копия информационной базы
1С. Продажи за меньший диапазон внутри уже скачанного периода фильтруются локально
по датам документов. Более широкий диапазон, новые справочники или новый период
маржи требуют первого фонового получения своего снимка. Для маржи сохраняются
точные периоды: оценку себестоимости на конец периода нельзя произвольно складывать
по дням. Открытие уже сохранённого диапазона работает при недоступной 1С.
Чеки, продавцы, склад и перемещения пока используют существующие источники напрямую.
Формулы расчёта маржи и набор документов остаются в существующих загрузчиках.
Следующий этап для произвольных SQL-срезов — хранение отдельных документов,
движений и версий справочников с проверенной полнотой синхронизации.

Для возврата к прямым запросам установите `ONEC_LOCAL_ANALYTICS=false` и
перезапустите API. Сохранённые снимки при этом не удаляются.
